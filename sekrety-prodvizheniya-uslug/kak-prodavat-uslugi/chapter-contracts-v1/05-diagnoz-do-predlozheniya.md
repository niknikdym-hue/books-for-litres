# CHAPTER CONTRACT V1 — 05

**Book:** «Как продавать услуги»  
**Working title:** «Диагноз до предложения»  
**Status:** PLANNED / ARCHITECTURE-DRAFT  
**WRITING_ALLOWED:** NO

## BUSINESS PROBLEM
Продавец слишком рано принимает stated request за реальную задачу и предлагает стандартное решение; клиент затем сравнивает нерелевантные предложения по цене или вообще не видит связи с проблемой.

## UNIQUE QUESTION
Как получить достаточно точное понимание задачи и decision context до design of offer — без manipulative script?

## MECHANISM
`stated request ≠ full problem → premature solution → problem–solution mismatch → weak relevance / price comparison / no-decision`.

## DECISION
Решить, достаточно ли информации для предложения и какие information gaps ещё необходимо закрыть.

## ACTION / ARTIFACT
**Diagnostic Conversation Map**: current state, desired change, constraints, consequences, success criteria, participants/decision, missing info.

## OBSERVABLE CHECK
После разговора продавец может описать situation клиента его языком, назвать success criteria и явно перечислить unknowns.

## EVIDENCE FUNCTION
Professional-service diagnosis/co-production; complex-sales questioning as benchmark; problem-definition literature.

## WORLD-CLASS BENCHMARK
SPIN = research discipline. Не копировать question sequence. Contribution: information-gap diagnosis tied to buyer uncertainty and service design.

## RUSSIA APPLICATION
Separate model B2C self-employed expert, owner-led B2B, multi-stakeholder B2B.

## FRESHNESS
Core evergreen. Российские examples recheck only for current business/legal specifics.

## SCENE / CASE
Model: клиент просит «рекламу», «сайт», «обучение» или «аудит», но stated solution hides another problem. Не превращать в рекламу канала.

## ANALOGY
NONE RESERVED.

## NOT THIS CHAPTER
Не решает qualification/no-go; не пишет proposal; не даёт universal script; не обрабатывает objections.

## COMPOSITION
Premature prescription → why request is incomplete → information gaps → complication: client may not know problem either → diagnostic map.

## UNIQUENESS
Only Ch5 defines **what must be learned before proposing**. Ch6 decides whether parties should proceed after enough is known.
