# SERIES PRODUCTION PROTOCOL — «Инструменты интернет-маркетинга»

**Статус:** CANONICAL / BINDING production authority  
**Дата:** 2026-09-07

## 1. Сначала серия, потом отдельная книга

До начала Writing любой книги перезапуска провести **Series Portfolio Re-Architecture 2026+**.

Обязательный результат этапа:

- фактическая карта legacy-книг;
- карта современного digital-marketing landscape;
- карта сильных мировых benchmark territories;
- карта реальных российских задач и ограничений;
- список крупных reader problems;
- overlap/merge risks;
- candidate book territories;
- решение для каждой legacy territory: `KEEP / REFRAME / MERGE / RETIRE / RESEARCH-ANEW`;
- proposed новые территории без автоматического утверждения названий;
- owner-approved portfolio map.

Пока portfolio map не утверждён, ни одна старая книга не получает автоматический статус «переписываем первой».

## 2. Legacy inventory

Для каждой старой книги определить:

- что в ней было центральным promise;
- какие вопросы всё ещё актуальны;
- какие механизмы evergreen;
- какие факты/инструменты устарели;
- что стало банальным/AI-replaceable;
- что требует нового research;
- что пересекается с другими legacy/new territories;
- оправдывает ли тема отдельную книгу сегодня.

Старый текст не формирует новое оглавление.

## 3. Series Market / Problem Map

До book portfolio decision исследовать не «темы, о которых можно написать», а **дорогие/частые решения российского бизнеса в digital-маркетинге**.

Для каждой problem territory фиксировать:

- reader;
- decision;
- cost of error;
- current free/AI substitutes;
- global knowledge base;
- Russia-specific execution constraints;
- time-sensitivity;
- потенциал для сильной самостоятельной книги.

## 4. World-Class Category Map

Для каждой потенциальной книги до Book Definition сравнить:

- 3–5 сильных международных книг/авторов/моделей;
- профессиональные research programmes / standards / practitioner systems;
- сильные современные free resources;
- лучший доступный AI-ответ.

Нужно доказать не «чем мы отличаемся», а **почему наша книга даёт дополнительную интеллектуальную и практическую ценность**.

## 5. Book Definition

Book Definition включает минимум:

- reader and real situation;
- expensive/frequent problem;
- central promise;
- central mechanism / causal model;
- original contribution hypothesis;
- reader before / after;
- practical end state;
- `NOT THIS BOOK`;
- series territory / overlap proof;
- AI-substitution proof;
- target length;
- freshness profile;
- Russia application intent.

Definition утверждает пользователь.

## 6. Research Map

До Architecture классифицировать claims/questions:

- `EVERGREEN_MECHANISM`;
- `TIME_SENSITIVE`;
- `PLATFORM_SPECIFIC`;
- `LEGAL_REGULATORY`;
- `MARKET_DATA`;
- `AI_CAPABILITY`;
- `AUTHOR_OBSERVATION`;
- `HYPOTHESIS`.

Для каждого research item заранее определить, **какую функцию он выполняет в argument**.

Не собирать источники ради количества ссылок.

## 7. Russia Application Map

Для каждой materially relevant книги/главы зафиксировать:

- российский reader context;
- available channels/platforms;
- B2B/B2C distinctions;
- data/analytics constraints;
- regulatory constraints;
- economics/operational reality;
- какие зарубежные рекомендации требуют адаптации;
- что должно пройти re-check перед master.

## 8. Practical Value Map

До Writing должна существовать карта:

`chapter problem → decision → action → artifact/output → observable check`

Если глава не меняет решение/действие читателя и не выполняет уникальный интеллектуальный шаг — `MERGE / DELETE / REWORK`.

## 9. Architecture

Каждая глава обязана иметь:

- unique question;
- unique mechanism / causal chain;
- contribution;
- reader shift;
- evidence function;
- practical result;
- Russia application where relevant;
- freshness risk;
- `NOT THIS CHAPTER`;
- overlap exclusions;
- composition intent;
- deletion test.

Число глав не задаётся заранее.

## 10. Chapter admission

Architecture approval резервирует территории, но не открывает Writing глобально.

Каждая глава получает `WRITING_ALLOWED=YES` только после:

- research/evidence PASS;
- world-class PASS;
- original contribution PASS;
- practical value PASS;
- Russia application/freshness PASS;
- uniqueness PASS;
- boundaries PASS;
- deletion/AI-substitution PASS;
- anti-junk readiness PASS.

## 11. Writing

Писать строго по function главы.

Запрещено:

- добавлять интересный материал из соседней/будущей книги;
- объяснять тот же mechanism новым каналом;
- дополнять объём списками/чек-листами без новой функции;
- вставлять свежую цифру без evidence;
- использовать platform feature без актуальной проверки;
- вставлять AI ради современности;
- выдавать model/composite case за реальный.

## 12. Chapter QA

После каждой главы до перехода дальше:

- contract fulfillment;
- causal clarity;
- evidence integrity;
- practical output usefulness;
- Russia applicability;
- freshness status;
- intra-book overlap;
- series overlap;
- prose/anti-AI quality;
- target-length density.

## 13. Mid-book audit

После 40–60% manuscript проверить:

- drift от central promise;
- repeating mechanisms;
- repeated chapter rhythm;
- слабую practical density;
- platform-detail bloat;
- future-book leakage;
- stale facts accumulated during writing;
- volume padding;
- AI-smell.

Структурная проблема → Architecture/Contract REWORK, а не косметическая правка.

## 14. Whole-book edit

Порядок:

1. central promise fulfillment;
2. intellectual progression;
3. duplicate mechanisms;
4. contribution strength;
5. practical-system completeness;
6. evidence/facts;
7. Russia application;
8. freshness;
9. cases/examples;
10. composition/rhythm;
11. anti-AI prose;
12. language;
13. reader read-through.

## 15. Adversarial Review

Перед Literary Master отдельный независимый проход ищет причины **не выпускать** книгу:

- банальность;
- AI-replaceability;
- fake novelty;
- weak evidence;
- stale platform advice;
- pseudocases;
- hidden repetition;
- weak practical outputs;
- Russia mismatch;
- unnecessary length;
- internal editorial leakage;
- marketing clichés / AI prose patterns.

## 16. Freshness closure

Перед master:

- повторно проверить все time-sensitive items;
- записать дату проверки;
- удалить/ослабить неподтверждённое;
- убедиться, что central argument не зависит от быстро стареющей детали.

## 17. Literary Master

Literary Master содержит только читательский текст.

Запрещены внутренние статусы, TODO, editor notes, authority references, anti-junk labels, model instructions и production metadata.

## 18. Series closure

После owner acceptance:

- exact Literary Master фиксируется;
- used mechanisms/tools/cases/functions → `USED-ACCEPTED`;
- книга входит в exclusion corpus;
- unused reservations могут быть released только по фактическому master;
- обновляется portfolio/canon;
- только затем открывается следующая book Architecture.

## 19. New books

Новые книги серии не придумываются из списка популярных ключевых слов.

Candidate book становится реальным только если одновременно доказаны:

- значимая reader problem;
- самостоятельный mechanism/contribution;
- высокая practical value;
- недостаточность сильного AI/free substitute;
- применимость в России;
- разумная устойчивость к устареванию;
- отсутствие overlap с другими книгами.

Финальное добавление книги в серию — только по решению пользователя.
